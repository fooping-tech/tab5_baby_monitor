# 実機テストと受入条件

## 自動テスト

ホスト側のCTestは滞在時間境界、ヒステリシス、エラー、NaN/範囲拒否、古い入力、重複時刻、
時刻の巻き戻り、無効設定を検証します。Pythonテストは集計計算と不正入力を確認します。
どちらも検出器の精度を証明しません。CSV fixtureは意図的に合成データであり、測定済み精度ではありません。

```sh
python3 tools/evaluate_presence.py /private/evaluation.csv
```

入力CSVの形式は次です。

```csv
session_id,timestamp_ms,truth,prediction,pipeline_ms
synthetic,0,present,unknown,2100
```

`truth` は対象とROIについて独立に注釈した `present` / `absent`、`prediction` は
`present` / `absent` / `unknown` です。baby用評価では、COCO personモデルが検出する大人を
赤ちゃん在室の正解に数えません。成功フレームだけではなく、予定した観測と失敗もすべて記録します。

集計器は混同行列、precision、`unknown` をmissと数えるrecall、unknown率、全フレームaccuracy、
推論時間のnearest-rank p50/p95を返します。定義できない比率は0ではなく `null` です。
これはフレーム加重であり時間加重ではないため、不規則サンプリングは欠損を記録して別途時間/イベント指標を計算します。
このツールは推論実行やシリアルログ解析を行いません。

## モデル品質の受入条件

- 最終評価前に、子ども/家庭/セッションが交差しないテストセット、しきい値、モデルmanifestを固定する。
- 検出はmAP50、mAP50-95、person/babyのprecision/recall、box品質、養育者/人形の誤検出を測る。
- 在室は陽性recall、false-absent時間、false-present回数/時、入退室遅延p50/p95、unknown率を測る。
- 照度/IR、動き、隠れ、カメラ角度、距離、対象、毛布で層別し、難しい条件を平均値で隠さない。
- 同一画像でFP32、量子化エミュレータ、デバイス出力を比較し、私有の失敗例を人手で確認する。
- 将来の姿勢分類は3クラス混同行列、クラス別precision/recall、拒否率、較正、層別失敗を測る。安全性は主張しない。

## Tab5実機テスト

以下は順番に、個別の証跡として実施します。ビルド・フラッシュ・ライブ映像・精度・長時間試験を一つにまとめません。

1. ボードrevision、flash/PSRAM、モデルSHA256、IDF revision、ファームウェアSHA256、電源、JPEG利用権を記録する。
2. ビルドとサイズ確認後、対象ポートを確認してから手動承認でフラッシュする。フラッシュ検証結果を保存する。
3. 権利確認済みの静止画で復号、`valid=1`、box/scoreの妥当性を確認する。単一画像での在室状態が`unknown`なのは正常。
4. USBカメラではRGB/回転、新しい時刻、AI/RTSPバッファの独立解放を確認する。ROIは未実装。
5. 復号、前処理、推論、後処理、合計遅延、FPS、内部/PSRAM空き、スタックHWM、フレームdrop、切断/再接続、古い結果の扱いを測る。
6. UVC抜線、確保失敗、推論停止を試し、消費者が誤った安心ではなく`unknown`を返すことを確認する。
7. AI+RTSPを同時に検証してから、立会いの1時間試験、延長試験、再起動復旧を行う。

現時点ではJPEG/AIのCPU負荷に起因するウォッチドッグ事象があるため、長時間安定性は未達です。
画面、Scrypted/HomeKit、意図的なウォッチドッグ障害注入は別の受入項目です。実施済みの事実は
必ず [PLANS.md](../PLANS.md) を参照してください。私有画像を含むログやファームウェアをPRへ公開しません。
